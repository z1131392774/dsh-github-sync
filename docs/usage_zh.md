# 用法

*[English](usage.md)*

面板就是全部界面：两列、一排操作、顶部一行状态。凡是写到GitHub的动作，都先过一遍你确认的预览——东西离开你的机器之前你就看清了，不会事后才发现。

## 面板

![面板](panel.png)

```
┌ device / repository / branch / current workspace ────── ● connected ┐
├──────────────────────┬───────────────────────────────────────────────┤
│ remote repository    │ local sessions (workspace dropdown)           │
│ 💬 sessions (tickable)│ ☑ session…   size   time                     │
│ 📄 files (tickable)   │                                               │
├──────────────────────┴───────────────────────────────────────────────┤
│ selected: local N · remote sessions M · remote files K                │
│ [Preview upload] [Folder…] [Download sessions] [Download files]       │
└──────────────────────────────────────────────────────────────────────┘
```

**工作区下拉框**决定右列显示哪些本地会话。默认值取你此刻在DSH里看的那个工作区，而这偏偏经常不是目标——下载前先看一眼：会话下载到哪个工作区，就归哪个工作区。

## 同步徽标

本地每行的徽标来自一处比对：本地文件的正文散列对远端索引。

| 徽标 | 含义 |
|---|---|
| Synced | 两边字节相同 |
| Local ahead | 你在这台机器上又聊了；上传它 |
| Remote ahead | 另一台机器推过；下载它 |
| Not uploaded | 从未上传 |
| Active | 最近五分钟写过；上传只是给移动中的文件拍快照 |

搜索、**只看未同步**、**选中未同步**、**同步此工作区（N）**，图的是「什么还没传上去」不必靠记。

## 传输

长传输显示单文件进度——`12/30 · uploading · f12.bin`——预览阶段（读会话、列远端目录树）和提交阶段（上传blob、建目录树、写提交）都带进度。

- 点进度条旁的`▸`展开文件列表：每项显示等待中、传输中、已完成、已跳过。
- 还没开始传的文件都能**跳过**。跳过附件会同时从`manifest.json`摘掉它的引用，不留悬空记录。
- **取消**在文件之间生效。`ref`不更新，传了一半不会在仓库里留下提交。
- 传输状态存在宿主进程里，不在浏览器里：切走再回来，进度条自己接上；没确认的预览也会恢复。
- 面板状态——选中的工作区、勾选、开关——刷新后还在，存在浏览器里。

## 设备和历史

**设备**列出远端索引里记录的每台机器和各自最近活动，本机带标记。**历史**是最近的上传、下载日志（文件数、提交、失败），追加到`$DSH_HOME/github-sync/history.jsonl`。

## 删除

两边各自独立；每次删除在四秒内问两次。

- **本地行的垃圾桶**只删这台机器上的会话，仓库里留着。没有别处引用的附件，在本地清理掉。
- **远程行的垃圾桶**只删仓库里的这份，这台机器还留着。没有别处引用的附件，在远端清理掉。

## 冲突

两边改过同一条会话时，预览把该行标成`blocked`，请你定夺：

| 选择 | 效果 |
|---|---|
| Download first | 先拉远端副本，再定 |
| Force local over remote | 用这台机器的版本 |
| Force remote over local | 用仓库里的版本 |

两个强制动作都立即生效，并重跑预览。所以列表永远显示接下来会发生什么，不是过去发生了什么。

一条会话只属于一个工作区。下载指向第二个工作区时，即使强制，计划也以`blocked`拒绝——先在那儿解除关联，或者下载到头帧`cwd`已经匹配的工作区。

## 仓库变大

每次上传都写一个新blob，GitHub自己不回收旧的。会话待在固定路径（`<project>/sessions/<id>.jsonl.zstd`），历史只占空间，不碍事。

- 要回收：`git clone --mirror`，用`git filter-repo`改写，或者开个新仓库重新上传。
- 为了交接而不是存档，一个项目一个仓库，比一个仓库装所有项目更经用。
- 想先估量大小，**诊断**会报告当前远端的会话数和附件数。

## 首次运行

没配仓库时，横幅给出**开始配置**：建空的私有仓库、建细粒度令牌、两个都粘贴、测试。每一步都链到它需要的那个GitHub页面。见[配置](setup_zh.md)。

## 让agent干活

插件注册了三个工具，你不必记命令，照常说话就行：

- 「把这条会话推到GitHub」——`github_sync_transfer`带`phase: preview`返回计划；同一个工具带`phase: execute`和预览令牌才执行。
- 「远端仓库里有什么？」——`github_sync_remote_list`。
- 「连接还好吗？」——`github_sync_status`。

agent跳不过预览：令牌由宿主签发，没有它，execute失败。
