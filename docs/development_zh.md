# 开发指南

*[English](development.md)*

怎么改这个插件，怎么判断改完了。文档标准在 [docs/AGENTS.md](AGENTS.md)；常驻规则在[根目录的 AGENTS.md](../AGENTS.md)。

## 代码长什么样

`index.js` 跑在宿主进程里：HTTP 路由、三个 agent 工具、状态文件都归它。`client.js` 跑在浏览器面板里，原样发布，没有打包器改写它，也不能往里 import 依赖。`lib/` 放两边都要打交道的部分——会话文件格式、plan builder、GitHub 客户端。

plan builder 在要紧的意义上是纯的：它读本地磁盘和远端索引，返回动作清单，一个字不写。所有写操作都发生在之后，在一处，手里拿着计划。保持这样；计划兼着执行，预览就诚实不了。

## 改动纪律

1. **先懂再改。** 目标文件、它旁边的文件，凡是碰到会话格式的，先读 [`lib/zstdframe.mjs`](../lib/zstdframe.mjs) 和 [`lib/sessionlog.mjs`](../lib/sessionlog.mjs)。
2. **计划写下来。** 改什么、可能坏什么、怎么验。超过三条，说明这次改动一次做不完。
3. **动最小的面。** 扩展现有的路由或 builder，别平行再加一个。
4. **随手删。** 这次改动让什么过时了，删掉，链到它的链接也修好。
5. **提交要看得懂。** 一次提交一个逻辑改动；提交信息说为什么。

## 失败与错误处理

- **边界上校验。** 路由 body、远端索引条目、会话 id 都来自外部；趁它们还没变成路径，先查。
- **拒绝，不将就。** 公开仓库、不安全的路径段、不认识的会话版本，一律拒掉，消息里写明原因。绝不拿默认值顶替然后继续。
- **结果不明就停下报告。** 批次做了一半，报告哪些落地了、哪些没有，不宣称成功。
- **保住根因。** 包一层上下文，原始消息留住。日志记一次，记在处理错误的地方。
- **忽略的错误要点名。** 空的 `catch` 要写清它预期什么、为什么继续往下走是安全的。

## 验证阶梯

跑能抓住这个错误的最便宜的检查，跨边界时才扩大范围。

1. **聚焦。** `node tools/selftest.mjs` 过一遍纯逻辑——帧解析、头部重写、正文比对、路径编码、guard 函数。
2. **计划层测试**，改了动作怎么定就跑：`node tools/test-upload-plan.mjs`、`node tools/test-force.mjs`、`node tools/test-guards.mjs`、`node tools/test-filesync.mjs`。
3. **安全审计**，加了路由、import 或网络调用就跑：`node tools/audit-safety.mjs`。
4. **在 DSH 里手跑**，改动影响用户看到的东西时：重载插件，打开面板，把那条路径走一遍。
5. **文档：** `npm run check`。

报告命令和它打印了什么。「应该能过」不算结果。有东西在这里跑不了，点名，说为什么。

## 复查清单

交活前，把自己的 `git diff` 从头到尾读一遍。

- diff 只做一件事吗？提交信息说了做什么、为什么吗？
- 每个改过的文件都有理由吗？没有格式噪音和调试输出吗？
- 远端给的值，只有过了 guard 才变成路径吗？
- 预览路径还是一个字节都不写吗？执行路径还在消费它的预览令牌吗？
- 错误还留着根因和中文文案吗？
- 文档和中文版还跟行为一致吗？
- 代码、测试、日志里没有令牌、设备 id 和绝对路径吗？
- 别人撤掉其中一块，会有测试或审计失败吗？不会，那块就没验过。

## 决策记录

决策记录存一个比它的 diff 活得久的决定：一个格式、一次拒绝、一笔将来的维护者还会再吵的取舍。记录放在 [`.agents/notes/`](../.agents/notes/README.md)，状态写在文件夹名里。作决定的同一次改动里写记录；已经有那份就更新它，别另开一份。

决策记录不是变更日志，也不是教程。读者要的是当前行为，代码和文档里有。

## 发布

发布前的清单归 [releasing.md](releasing.md)。升 `version`、往 `CHANGELOG.md` 加条目、跑审计、两个平台都验一遍，然后才打 tag。
