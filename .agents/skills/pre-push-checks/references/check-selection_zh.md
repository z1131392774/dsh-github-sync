# 挑选最窄的检查

*[English](check-selection.md)*

规矩看覆盖，不看省事：改动错了会挂的才跑；错了也照样过的，别跑。

## 举个例子

你改了 `lib/sessionlog.mjs` 里的正文前缀比对，又给 `tools/selftest.mjs` 加了一个用例。

- `tools/selftest.mjs` 覆盖新分支和旧分支。
- `tools/test-upload-plan.mjs` 只有当计划路径调到那个函数时才增加覆盖——去搜这个调用，别假定。
- 改动只限于比对逻辑，而它从不碰这块，`tools/test-upload-plan.mjs` 就不会挂。

这是一条命令，不是三条。跑一遍全套不算勤勉，只会平白声称一件你无须验证的事。

## 改动跨过边界时，放宽

- **共用的辅助函数：** 每个调用方都继承这次改动。跑调用它的那些模块的测试。
- **默认值、上限或配置键：** 行为在你没碰的代码里变了。跑读取它的代码的测试。
- **会话格式、manifest 结构或远端目录布局：** 旧仓库必须照常工作，新仓库必须保持可读。两个方向都试，并把 `tools/test-multidevice.mjs` 留在范围内——它走的合并路径最先垮。
- **决定一次写入的东西：** 路径、id、sha、跳过规则。`tools/test-guards.mjs` 和 `tools/test-boundaries.mjs` 就是为这个存在的，selftest 全绿不算证据。
- **打包：** 用户装的是产物，不是源码。`pnpm pack`，解开，核对 README 链接到的每个文件都在包里。
- **平台相关代码：** 检查得在那个平台上跑。Windows 上全绿，说明不了 macOS 的会话目录。

## 什么时候放宽到全套

- 改动波及全仓库：测试辅助函数、`tools/` 的约定、导出面。
- CI 挂了，你在复现它。
- 用户要求的。

## 什么不算证据

- 读了代码，断定它没错。
- 测试断言的是你刚写的实现，它承诺的行为却没测。
- 改动前通过、改动后没重跑的检查。
- 在另一个提交、分支或工作副本上跑的检查。
- 只改了 `docs/*.md` 就跑 `npm run check`——它证明的只是文档，代码它管不着。
