# 决策记录

*[English](README.md)*

决策记录写得很短，留给下一个改这份代码的人。代码说明发生了什么，文档说明怎么用，决策记录说明我们为什么这样选、否掉了什么、付出了什么代价。少了这份记录，半年后同一场争论再来一遍，信息更少。

一项决定，一份记录。决策记录不是更新日志、任务清单或教程。

## 目录与命名

决策记录放在 `.agents/notes/{lifecycle}/YYYY-MM-DD-topic-slug.md`。文件夹即状态，状态变了，记录就换文件夹。日期取议题首次提出的那天，之后怎么改都不动它；编辑历史 git 都记着。

- **`proposed/`** —— 实现前评审过，或者还没开工。
- **`implemented/`** —— 决定已上线。事实往前走，记录跟着更新，保持如实。
- **`rejected/`** —— 考虑过，否决了。只要其中的理由还能挡住一次差不多的重提，就留着。

目录树就是清单。别加索引：路径重复一遍，每处不相干的改动还会变成冲突。

## 什么时候写

理由比 diff 活得久，就随那个改动写下或更新决策记录：一种文件格式、一个看着出人意料的拒绝、一句跨 DSH 版本的兼容承诺、一项还会被翻出来重吵的取舍。

机械性修改、文案改动、原因测试已经讲清的 bug，跳过不写。该更新的是掌管那项决定的记录，别另起一份。

## 文件格式

前三行固定：

```markdown
# Note: <title>

Status: <proposed | implemented | rejected — one-line reason>
```

Status 与文件夹一致，不带日期。

正文以 `## Problem` 开头，写到不依赖解法也看得懂。

**`proposed/`**：`## Problem`、`## Proposal`、`## Alternatives considered`、`## Acceptance criteria`、`## Risks`。

**`implemented/`**：`## Problem`、`## Decision`、`## Alternatives considered`、`## Consequences`。

`## Decision` 用现在时。implemented 记录里不放计划和清单：做了就是做了，没做就是没做。`## Testing` 和 `## Deferred` 陈述的是当前事实，可以留。

**`rejected/`** 保持提案时的结构，结论写在 `Status:` 那一行。

**`## Alternatives considered` 必写。** 每个认真考虑过的备选方案，连同落选的原因，一段一个，段首加粗。备选方案只能记录，不能编造；理由丢了，用一行说明丢了。

## 让 implemented 记录保持如实

决策记录写的是已上线的现状，事实变了它就变：文件改名、路由搬家、默认值更换——跟着同一个改动更新。决定本身不重写；决定变了，这份记录就让位，断不改写成自己的反面。

旧记录可以并进继任者再删除，前提是继任者保下它全部独有的理由、备选方案和后果。

## 删除与否决

- 只记了机械性修改的 implemented 记录，连同指向它的链接一起删。
- rejected 记录再拦不住同样的错了，就删。
- 别为了吵赢删记录。取代它，并说清什么让你改了主意。

和其余文档一样，每份记录都是双语：`<topic>.md` 和同文件夹的 `<topic>_zh.md`。英文是源。
